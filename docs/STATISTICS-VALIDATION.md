# Приёмка RAM/web 0.2.0

Проверки выполнены на отдельном CHR RouterOS 7.24.5 amd64. Рабочий MikroTik
не подключался и не менялся. Нативные восемь RSC файлов остались прежними.

## Код и артефакты

- 193 Python unit-тест, включая настройки, ограничения private CIDR, запрет
  WAN/bridge, swap, точность и порядок firewall scopes.
- 12 Rust base-тестов, 27 Rust-тестов с feature `web`: выбор WAN, codec,
  ограниченный observer API transcript, очереди, кольца, epoch, secret redaction,
  размер максимального экспорта, HTTP auth/origin/methods/queries/deadlines.
- 6 новых offline Windows/Tk проверок web и прежние 6 проверок мастера создания.
- Шесть scratch-образов: base/web × amd64, ARM64, ARMv5; один статический ELF,
  UID65532:65532, один слой, отсутствие dynamic loader, settings и secrets.
- SHA256 tar/gzip/binary/image-config и готовые Docker contexts проверены.
  Image ID импортированного CI web amd64 совпал с build report GitHub Actions.
  Все шесть образов совпали побайтово между двумя независимыми PR CI сборками.

## CHR

`tests/container_web_acceptance.py --reboot` прошёл 11 проверок:

1. Доступ через LAN, статические assets, bearer; неверные методы, Origin, ключи,
   token-query и чрезмерная история отклоняются.
2. SLA, RX/TX, политики и экспорт доступны; пароль API, web-token и owner credentials
   отсутствуют в JSON.
3. Прямой HTTP-запрос с ISP/WAN попадает в owned firewall deny.
4. Регулярный опрос/экспорт в течение 66,2 с: RAM-история растёт, проверяемые файлы
   не меняются, RSS ниже 2 МиБ.
5. Отключение и возврат WAN link при медленных HTTP-заголовках не прерывают lease;
   наблюдаемое переключение — 0,91 с после административного link down. Это не
   гарантия времени обнаружения удалённого отказа: его определяют SLA таймеры.
6. Остановка контейнера оставляет рабочий нативный fallback.
7. Повторный запуск очищает RAM-историю и возобновляет container control.
8. SIGKILL приводит к истечению lease и переходу на нативный fallback.
9. При runtime off удаляются web settings/ACL и отдельная observer API-сессия;
   маршрутизация остаётся активной, active JSON не меняется.
10. Повторное включение переиспользует отдельный токен и создаёт новую RAM-историю.
11. Reboot меняет boot fence, очищает историю и автоматически запускает
    web/controller из установленной конфигурации.

## Память и запись

Сценарий: три WAN, два SLA-профиля, четыре политики, sample10с/history360,
существующие Netwatch-пробы, HTTP status каждые 2с и периодический export.

| Показатель | Результат |
|---|---:|
| Длительность | 66,2 с |
| RSS процесса | 851 968–856 064 байт (832–836 КиБ) |
| RouterOS `memory-current` контейнера | 598 016–724 992 байт |
| Метаданные/содержимое проверяемых файлов | без изменений |
| `/proc/self/io` на этом CHR | недоступен, `write_bytes=null` |

`memory-current` и RSS имеют разный учёт и не заменяют друг друга. Замер короткий,
не показывает максимум для 16 WAN ×600 точек и не является испытанием физического
ARM. Число точек, событий, строк, размеров ответов и очередей отдельно ограничено
кодом и unit-тестами. Нельзя называть отсутствие `/proc/self/io` измеренным нулём.

До/после сравнивались точные метаданные и SHA256 пяти файлов: active JSON, intent,
mounted controller settings, API-password и web-token. Во время стабильного окна
не было смены выбора WAN/владельца. Действительные переключения отдельно могут
записывать intent, как и в базовом контроллере. Проверка не утверждает отсутствие
всех записей всей RouterOS или любых пользовательских disk log действий.

Collector делает только ограниченные identity/interface-print запросы; transcript
проверен unit-тестом. Статистика не вызывает file/set и не открывает файлы на
запись. Mounts настроек/секретов RO, container logging выключен. Подготовка
требует отсутствия включённого swap; `swap-max=1` служит дополнительным лимитом,
поскольку значение0 в RouterOS 7.24.5 означает unlimited.

## Браузер

В отдельном проходе реальный Chrome через LAN-путь проверил три карточки WAN,
четыре политики, SVG-график, скачивание JSON на компьютер, отсутствие данных в
localStorage/sessionStorage, очистку поля токена и выход. На ширине390px нет
горизонтального переполнения страницы; ошибок JavaScript не обнаружено. HTML,
CSS и JS встроены в бинарник, CDN не используется. Таблица событий ограничена
высотой360px и прокручивается внутри панели.

Сырые отчёты, browser downloads, screenshots, credentials и архивы восстановления
сохраняются только в локальном `runtime/` и не входят в репозиторий/release.
