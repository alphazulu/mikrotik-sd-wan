# Следующая итерация статистики

Русский | [English](STATISTICS-NEXT.en.md)

**Проект, без изменения текущего контейнера.** Работающий web и его настройки
описаны в [STATISTICS.md](STATISTICS.md). Эта страница не объявляет новые поля API
или GUI реализованными и не меняет текущий длительный прогон.

## Разделение показателей

| Группа | Предлагаемые показатели |
|---|---|
| MikroTik целиком | CPU, свободная/полная RAM, uptime, время и свежесть замера |
| Процесс контейнера | RSS, CPU ticks и вычисляемая загрузка только при известной частоте тиков и корректном интервале |
| Канал | RX/TX, RTT, джиттер, потери, carrier/IP, SLA и возраст проб |
| Политика | Выбранный WAN, причина, время последнего перехода, обслуживание/drain |

CPU процесса нельзя подписывать как CPU роутера. Отсутствующий счётчик — `null`
с понятным пояснением. После reboot, смены epoch или сброса байтовых счётчиков
разность не превращается в отрицательную или огромную скорость. Период/единицы
измерения видны пользователю; график отделяет пропуск данных от нуля.

## Бюджет и хранение

Все новые данные остаются в ограниченных RAM-буферах и выключены вместе с модулем.
Нет БД, фоновых checkpoints, access logs или периодической записи на flash.
Экспорт создаётся только по явному действию на компьютере пользователя.

Для ресурсов роутера предлагается редкий общий API-снимок, например раз в 10 секунд,
с повторным использованием результата всеми читателями. Частота браузера не должна
повышать частоту API-запросов или задерживать цикл выбора WAN. Размер истории,
ответы и количество читателей имеют явные пределы. Значения периода и памяти
должны пройти измерение; это пока проектный бюджет.

## Переключения и приёмка

Время решения контроллера отделяется от фактического перерыва клиентского трафика.
Последний подтверждается внешним наблюдателем; по одному событию выбора WAN его
вычислять нельзя. Масштабирование графика не должно скрывать потерю данных.

Перед включением: 100% исполняемых строк/функций обоих Rust-профилей, `main` и JS;
ветви отдельно; ошибки API, stale, reset и лимиты проверяются assertions.
Затем — браузер, конкретный образ на изолированном RouterOS, влияние опроса на
выбор WAN и память. Испытуемый сейчас пакет остаётся неизменным; новый runtime
получает собственные доказательства, а не статус PASS старой версии.
