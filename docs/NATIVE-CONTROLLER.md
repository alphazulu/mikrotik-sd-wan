# Локальный SD-WAN на RouterOS

Русский | [English](NATIVE-CONTROLLER.en.md)

В нативном режиме решения выполняет `native/sdwan-controller.rsc`, установленный как `/system script sdwan-controller` на MikroTik. Scheduler запускает его каждую секунду. В контейнерном режиме локальный Rust предлагает выбор, а RouterOS проверяет и применяет его с нативным fallback: [CONTAINER.md](CONTAINER.md). Внешняя программа не собирает метрики для управления в цикле, не выбирает канал и не нужна после установки.

## Функциональность нативного ядра

- Независимые таблицы проб и исходные адреса WAN: `lookup-only-in-table` исключает проверку аварийного канала через резервный.
- Netwatch: ICMP для RTT/jitter/loss; контроль доступности через несколько `http-get`, `https-get`, `tcp-conn` или `dns` целей. HTTPS проверяет сертификат, DNS требует явный сервер.
- Кворум доступных целей и профили SLA, состояния unknown/healthy/degraded/down/recovering отдельно для каждого профиля/WAN.
- Плохие/хорошие окна, hold-down от последнего плохого измерения; одно окно Netwatch не засчитывается многократно при опросе scheduler.
- Потеря carrier обрабатывается сразу; застывшие измерения не остаются healthy.
- `prefer`: первый healthy из разрешённого списка. `strict`: ровно один разрешённый WAN без обхода через main. `allow_degraded` разрешает degraded только при отсутствии healthy и только в списке политики.
- FIB-таблицы, connection/routing marks для клиентов, входящих соединений и трафика самого роутера; симметричные ответы со всех WAN, включая DNAT. Local bypass исключает локальные назначения.
- При смене WAN удаляются записи conntrack изменившейся политики, включая возврат на приоритетный канал. Сессии других политик сохраняются. NAT остаётся стандартным.
- Журнал `SDWAN state …` и `SDWAN route …` на самом роутере; JSON состояния в global `sdwanStatusJSON` для диагностики.
- Нативные установка, согласование собственных объектов и откат к сохранённым флагам исходной маршрутизации. Объекты помечены `sdwan:v1:`. Секретов в JSON конфигурации нет.

Подробности маркировки, таблиц и очистки соединений — [DATAPLANE.md](DATAPLANE.md).

## Файлы конфигурации

Редактируемый исходник — `config/sdwan.json`. В RouterOS загружается компактный `sdwan-config.json`. После успешного согласования объектов установщик продвигает его в `sdwan-active.json`; контроллер читает только активную копию. Поэтому простое редактирование загруженного черновика не меняет работающий роутер.

| Раздел | Назначение |
|---|---|
| revision | Имя версии для оператора |
| health | Интервал, timeout, число пакетов, quorum, fail/recover окна, hold-down, stale timeout |
| wans | kind=static/dhcp/pppoe/lte/vpn, L3 интерфейс; apn_profile для LTE и транспорт VPN; address/gateway только для static; таблица проб, ICMP-цель и прикладные цели |
| sla_profiles | Пороги среднего RTT, jitter=max-min и потерь |
| policies | Клиент/подсеть, таблица, SLA, режим и порядок WAN |
| local_networks | Направления, которые всегда ищутся в main |
| takeover_route_comments | Явный список исходных default routes, отключаемых установщиком |
| takeover_rule | Исходное правило, заменяемое политиками SD-WAN |
| takeover_routes | Необязательные точные селекторы исходных default routes, включая маршруты без комментариев |
| disable_fasttrack | Необязательные селекторы правил FastTrack, отключаемых для policy routing |

Текущие таймеры ускорены для лаборатории: interval=2 с, fail=2 окна, recover=3 окна, hold-down=6 с. Это не утверждённые production значения. ICMP окно содержит 20 пакетов: единичная потеря равна 5%; для тонких порогов увеличивайте выборку/время наблюдения. Конфигуратор проверяет, что packet train вместе с timeout помещается в interval.

RTT и jitter задаются в миллисекундах с точностью до 0,001 мс, loss — в процентах до 0,01%. Скрипт конвертирует дробные JSON значения в целые масштабированные числа. Потери вычисляются из sent/response counts, а не из внутреннего фиксированного формата RouterOS `loss-percent`. В JSON состояния `rtt_us` и `jitter_us` — микросекунды; `loss_basis_points=100` означает 1%.

Любое изменение JSON применяется повторной защищённой установкой. Изменение активной конфигурации сбрасывает историю окон и повторяет прогрев. GUI кнопка установки и CLI `apply` загружают файлы, согласуют объекты и активируют новую версию. Топологию нельзя менять прямым редактированием активной копии.

## Графическая утилита Windows

Двойной щелчок `Configure-SD-WAN.cmd` в каталоге проекта. Либо:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Configurator.ps1
```

Используется Python с Tkinter; Windows GUI проверен с Tk 8.6. Мастер сначала подключается к API и читает устройство, затем пользователь выбирает внешние интерфейсы и цели. После генерации открываются формы WAN, SLA, клиентов и таймеров. Подробная инструкция — [CONFIGURATOR-WIZARD.md](CONFIGURATOR-WIZARD.md). Кнопки:

1. «Открыть» / «Сохранить» — обычный JSON-файл.
2. «Проверить» — локальная проверка конфликтов, адресов, кворума, таймеров и ссылок.
3. «Файлы RouterOS» — экспорт готового набора JSON + `.rsc` без подключения к роутеру.
4. «План изменений» — просмотр управляемых объектов и исходных объектов, принимаемых под управление.
5. «Установить на MikroTik» — backup и архив, локальный worker/watchdog, подтверждение новой API-сессией.
6. «Состояние» / «Журнал решений» — чтение текущих данных с самого MikroTik.
7. «Откат к исходному» — нативное восстановление сохранённых исходных флагов и удаление SD-WAN объектов.

URL лаборатории — `api://127.0.0.1:18728`; кнопка «Лаборатория» подставляет учётные данные из `runtime/credentials.json`. Для другого устройства введите URL, логин и пароль прямо в форме; identity определяется при чтении. Поддерживаются API TCP (`api://`), API TLS (`apis://`) и REST HTTPS. HTTP разрешён только для loopback. Для TLS проверяются сертификат и имя; можно указать CA. Адреса интерфейсов и NAT уже должны быть настроены на устройстве. Ядро поддерживает static, DHCP-client, PPPoE и native LTE IPv4 WAN. Для динамических каналов JSON задаёт kind и логический интерфейс без снимка аренды; создание клиента и его учётных данных выполняется заранее. LTE использует существующий APN профиль и interface gateway: [LTE.md](LTE.md). См. [DYNAMIC-WAN.md](DYNAMIC-WAN.md).

## CLI для разработки

Все команды из каталога проекта:

```bash
python3 sdwan.py validate
python3 sdwan.py bundle --output build
python3 sdwan.py plan
python3 sdwan.py apply
python3 sdwan.py status
python3 sdwan.py events
python3 sdwan.py disable
python3 sdwan.py enable
python3 sdwan.py rollback
```

`disable` останавливает только локальный scheduler и оставляет последнюю маршрутизацию. Для возврата к исходной конфигурации используется `rollback`. После закрытия CLI/GUI scheduler продолжает работать автономно.

`apply` проверяет identity, версию 7.24.5, интерфейсы и конфликты; сохраняет диагностический снимок. Установка выполняется локальным scheduler с независимым watchdog, зашифрованным полным backup и подтверждением из новой API-сессии. Ошибка или отсутствие подтверждения вызывает нативное восстановление и перезагрузку. Подробная процедура, права и ограничения — [DEPLOYMENT.md](DEPLOYMENT.md).

`sdwan-backup.json` отдельно хранит baseline-флаги принятых под управление routes/FastTrack и rp-filter. Кнопка «Откат к исходному» восстанавливает именно этот baseline. Аварийное восстановление неудачной установки возвращает полный снимок непосредственно перед ней.

Имена файлов `sdwan-*`, prefix `sdwan:v1:`, имена таблиц и script/scheduler проекта зарезервированы. Не запускайте два установщика параллельно. Стандартный экспорт содержит JSON и 11 RSC; ручной import обходит защиту, используйте штатный GUI/CLI.

## Лабораторные контрольные цели

`tools/probe_services.py` предоставляет три HTTP-цели на host loopback: 28081/28082/28083. Из каждого ISP они доступны через его QEMU host alias `10.77.N.2`. Пакеты edge → ISP → эти цели проходят ISP forwarding и NAT. Поэтому блокировка forwarding на ISP сохраняет ping его шлюза, но обрывает пробы.

```bash
python3 tools/probe_services.py start
python3 tools/probe_services.py status
python3 tools/probe_services.py fail a
python3 tools/probe_services.py heal
```

Команда `lab.py up` автоматически запускает эти цели. Это только имитация серверов в интернете, не контроллер. Три порта на одном компьютере не являются тремя независимыми операторами; для реальной эксплуатации замените их согласованными независимыми целями. Общий физический uplink и хост остаются общими точками отказа стенда.

## Проверки и ограничения первого среза

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/native_acceptance.py
python3 tests/native_numeric.py
```

Unit-тесты проверяют опасные ошибки конфигурации. Интеграционные тесты вводят отказы, а решения принимает только RouterOS: пути клиентов, quorum, дубликаты окон, отказ за доступным шлюзом, hold-down, разные SLA, strict, все WAN down, stale measurements, reboot, rollback и повторная установка. Набор изменяет только стенд и восстанавливает внесённые аварии в finally. Результат — `runtime/native-acceptance.json`.

Эти сценарии описывают исходный нативный этап. Динамические WAN, опциональный overlay и защищённое восстановление установщика теперь реализованы; их актуальная приёмка описана в [CURRENT-STATUS.md](CURRENT-STATUS.md). PCC/весовая балансировка, бесшовный перенос TCP при смене NAT IP, QoS, IPv6, расширенное управление секретами/ролями и постоянный журнал не заявляются реализованными. Политика качества опирается на окна проб и не является статистическим SLA за месяц или гарантией production. Следующие этапы — [ROADMAP.md](../ROADMAP.md).

## Группы, приложения и диагностика

Дополнительные policy selectors и top-level groups описаны в [POLICIES.md](POLICIES.md). Библиотека native links содержит ordering/match helpers и bounded RAM history; стандартный пакет — 11 RSC и JSON. Статус включает interface/APN, возраст проб, recovery/hold timers и причины выбора политик. [Диагностика GUI](DIAGNOSTICS.md) читает только свой status snapshot и active JSON; все решения остаются локальными.


Локальные `runtime/` отчёты, учётные данные и снимки устройств не входят в
репозиторий. Методика повторения проверок: [TESTING.md](TESTING.md).
