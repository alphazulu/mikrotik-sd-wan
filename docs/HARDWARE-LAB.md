# Физический ARM64-стенд с одним кабелем

Русский | [English](HARDWARE-LAB.en.md)

Этот сценарий использует отдельный hAP ax² и удалённую Ubuntu. Два клиента с
разными IP/MAC и два программных провайдера находятся в Linux namespaces.
Контроллер исполняется на физическом MikroTik: RSC либо локальный
непривилегированный Rust/scratch-контейнер. Служебный x86 L6 выполняет только
транспорт и L2-мосты; его диск — COW-копия лицензированного родителя.

```mermaid
flowchart LR
  C[Два клиента Ubuntu] --> L[Виртуальная LAN]
  L --> H[hAP ax²: SD-WAN]
  H --> A[Виртуальный WAN-A]
  H --> B[Виртуальный WAN-B]
  A --> S[Контрольные серверы Ubuntu]
  B --> S
```

Три линии EoIP проходят внутри общей SSTP-сессии с проверкой сертификата.
Единственный Ethernet-кабель остаётся подключённым к свитчу; тестовая LAN не
объединяется с физической сетью. DHCP и IP управления сохраняются. Перед
изменением default route закрепляется маршрут к управляющему узлу.

## Версия и пакеты

Опубликованная проверенная цель остаётся RouterOS 7.24.5. Для ограниченных
аппаратных проверок 7.25.1 требуется явное включение экспериментального режима:

```bash
export SDWAN_EXPERIMENTAL_ROUTEROS=7.25.1
python3 sdwan.py --config hardware.json --url apis://192.0.2.10:8729 \
  --credentials credentials.secret.json --ca lab-ca.pem --expect-identity lab plan
```

Это не включает поддержку произвольных версий. Без переменной 7.25.1 блокируется;
значение 7.26 не разрешает 7.26. Настоящая версия устройства не подменяется.
Пакет container должен совпадать с установленной RouterOS и архитектурой.
Каталог образов и их SHA256 остаются привязаны к проверенному коду Rust.

На проверенном устройстве 7.25.1 `/system/package/print` показывал также
доступные для загрузки пакеты: `available=true`, пустая версия и
`disabled=true`. Такой container не установлен и не предоставляет меню
`/container`. Подготовка распознаёт его как отсутствующую зависимость, а откат
RSC не вызывает недоступное меню. Ошибки чтения прав не скрываются.

## Проверки и границы

Аппаратная проверка RSC включает 32 TCP/UDP-потока с сопоставлением conntrack,
NAT и обоих направлений захвата на контрольном сервере. Проверены выбор по
клиенту и сочетанию IP + Address List назначения, отказ и возврат WAN-A по
доступности и состоянию интерфейса. Две закреплённые на WAN-B сессии продолжают
обмен в четырёх фазах; защищённый откат восстанавливает настройки управления.

Аппаратная проверка локального ARM64-контейнера прошла 25 проверок, включая
48 потоков TCP/UDP и шесть фаз сохранения закреплённых сессий. Подтверждены
отказ/возврат WAN-A, удаление старых NAT-привязок активных TCP/UDP и переход
Rust → резервный RSC → Rust при остановке и повторном запуске процесса. Откат
и восстановление DHCP-маршрута управления прошли отдельно. Архив scratch-образа
составляет 270 997 байт; исходники Rust не изменялись относительно проверенного
100% покрытия строк и функций. Это не измерение максимальной производительности.

Для общего туннельного транспорта явно выбран стендовый профиль: RTT 500 мс,
jitter 250 мс, потери 5%. Это параметры конкретного опыта, не рекомендации для
рабочей сети. Первый прогон с jitter 30 мс сохранён как неуспешный: измеренное
качество общего транспорта вызывало переключения во время проверки.

RouterOS может повторно использовать ID conntrack после удаления записи.
Наблюдатель должен сопоставлять исходный поток, NAT и марку; исчезновение ID
не является обязательным признаком завершения старой привязки. Отдельно
проверяются сохранение незатронутых потоков и новые двусторонние соединения.

Все линии используют один физический порт и общий транспорт. Результат не
подтверждает независимость настоящих провайдеров, LTE-радио, полную смешанную
матрицу PPPoE/DHCP/OSPF, предельную скорость Ethernet или повторную 48-часовую
приёмку. Расход CPU включает EoIP/SSTP. Аппаратная рекомендация режима остаётся
неизмеренной; отдельное сравнение ограниченного трафика на одинаковом транспорте
не заменяет тест требуемой рабочей нагрузки.

Резервные копии, сертификаты с ключами, учётные данные, реальные адреса и сырые
выгрузки остаются в приватном runtime. Состояние контроллера хранится в RAM;
периодическая запись статистики на NAND не включается.
