# Сценарии готовности конфигуратора

Русский | [English](CONFIGURATOR-CHECKS.en.md)

Статическое сопоставление существующих проверок на базе коммита `37a68a9`,
29 октября 2026. В шести наборах ниже **52 тестовых метода**; часть содержит
несколько случаев. Это не число уникальных сетевых испытаний и не новый запуск
тестов на документационной ветке. Общий результат SDK — [в текущем статусе](CURRENT-STATUS.md).

| Область | Существующие проверки | Набор |
|---|---|---|
| Платформа, пакеты, ресурсы | Недоступные поля/права, чужая архитектура, недостаток RAM, выключенный/несовпадающий пакет, отсутствие измеренного профиля | [8 методов](../tests/test_platform_support.py) |
| Носитель | Фактический mount, read-only/disabled/unmounted, неизвестное место, неверный путь, дубли mount, запрет загрузки до готовности | [12 методов](../tests/test_storage_readiness.py) |
| Device-mode | Только требуемые флаги, сохранение intent до отправки, потеря API без повтора, истечение/отмена, старый RAM-маркер, удаление только собственного worker | [10 методов](../tests/test_device_mode.py) |
| Передача и импорт | SHA256, частичная передача, неподходящий существующий файл, неверный URL/путь, точный image ID, отсутствие повторной записи, неопределённое состояние Fetch | [12 методов](../tests/test_provisioning.py) |
| LTE/RNDIS | Динамический DHCP роутера сохраняет LTE/APN; пользовательский DHCP-конфликт не маскируется ошибкой прав; исходная ошибка чтения сохраняется | [3 метода](../tests/test_rndis_inventory.py) |
| Сторонние mangle | Явный черновик, неизменность правил, raw/notrack и неполный снимок остаются блокирующими, сохранение sidecar-предупреждения, свежий preflight до payload | [7 методов](../tests/test_migration.py) |

Проверены утверждения и порядок блокировок, а не только имена методов. Для
перечисленных сценариев на этом этапе не выявлена необходимость дублировать
существующие тесты. Таблица не объявляет полное покрытие всех GUI-состояний:
реальные Tk-наборы, сохранённые API-снимки и CHR-проверки учитываются отдельно.

Если меняется поведение, добавляйте воспроизведение конкретного отсутствующего
случая и проверяйте наблюдаемый результат: «не готов» до загрузки/изменения,
сохранение чужого файла, отсутствие повторного update, корректная диагностика.
Не подменяйте этим проверки фактического импорта и восстановления на RouterOS.
