GUI при запуске не загружает лабораторный JSON в качестве конфигурации устройства. После чтения WAN не выбраны автоматически. В проверке выбраны `ether2`, `ether3`, `ether4`; `ether1` управления и `ether5` LAN не включались в WAN. Пример результата сохранён в `config/discovered-<identity>.json` (создаётся локально, не публикуется); комплект для ручного импорта — `build/wizard-sdwan-edge/`.

Сценарий установки создавал временный неосновной default route distance 250 и FastTrack, не совпадающий с трафиком лаборатории. Проверял отключение обоих установщиком и восстановление откатом. В `finally` объекты удалены, backup восстановлен, исходный `config/sdwan.json` снова установлен. Три WAN исправны, эмуляция потерь/задержек выключена, клиентские приоритеты восстановлены.

На CHR дополнительно проверены две особенности API: непрозрачные файловые `.id` и чтение `.rsc` больше 4 КиБ через `/file/get value-name=contents`. В rollback учтено, что отключённый маршрут с неявной таблицей `main` возвращает пустое `routing-table`.

## Повторение

В WSL из каталога проекта:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -q
python3 tests/wizard_acceptance.py
python3 lab.py verify
```

Интеграционный сценарий изменяет только лабораторный edge и восстанавливает его. Не направляйте его на рабочее устройство.

В PowerShell, при запущенном стенде:

```powershell
python .\tests\gui_wizard_smoke.py
```

Для обычного запуска приложения используется `Configure-SD-WAN.cmd`. GUI-тест не устанавливает конфигурацию на MikroTik; он выполняет чтение, генерацию, экспорт и plan. При наличии Pillow дополнительно сохраняет снимки окна; приложению Pillow не нужен.

Отчёты:

- `runtime/wizard-acceptance.json` — 4 live-проверки.
- `runtime/gui-wizard-validation.json` — Windows GUI.
- `runtime/verification.json` — состояние лаборатории после изменений.
- `runtime/screenshots/wizard-interfaces.png` (локальный отчёт).
- `runtime/screenshots/wizard-generated.png` (локальный отчёт).

TLS-код проверяет цепочку/имя сертификата, но соединение с реальным API-SSL сервером в этой итерации не испытывалось. Динамические WAN, VRF и сторонние routing marks не входили в подтверждённую поддержку этого этапа. Более поздние поддерживаемые методы и текущие ограничения — [CONFIGURATOR-WIZARD.md](CONFIGURATOR-WIZARD.md).

## Исправление ошибки «Создать конфигурацию», 23.10.2026

По `error.png` и сохранённой инвентаризации воспроизведён пустой IP/шлюз WAN, вызывавший необъяснённое `Address cannot be empty`. Добавлена проверка с именем интерфейса, переходом на шаг 1 и фокусом нужного поля. Рекурсивные маршруты больше не создают ложную неоднозначность между удалённой целью и фактическим шлюзом. Имена проб с точками со скриншота допускаются без переименования.

После исправления: **49 unit-тестов**, **6 проверок Windows GUI**. GUI-тест проверяет отсутствующий IP, неоднозначный шлюз, исправление поля без переподключения, успешное создание конфигурации с доменными именами целей и обработку сохранённой инвентаризации. Сетевых вызовов нет; конфигурация рабочего роутера не изменялась. Сохраняются проверки конфликтов существующих default routes и routing marks: исправление пустого поля не отменяет эти ограничения.

```powershell
python .\tests\gui_wizard_regression.py
```

Для проверки конкретной сохранённой инвентаризации этого обращения можно передать `--inventory <path-to-discovery.json>`. Отчёт — `runtime/gui-create-regression.json`; снимок успешного создания — `runtime/screenshots/wizard-create-regression.png`.
