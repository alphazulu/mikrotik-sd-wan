# Постоянные маршруты и RAM-допуск: исследование

Русский | [English](RAM-ROUTE-DESIGN.en.md)

Способ менять доступность маршрутов без `route disable/enable` найден и проверен
на изолированном CHR 7.24.5. Это экспериментальный вариант, **не включённый в
рабочий dataplane 0.4.0**. Его задержки и дополнительные условия требуют отдельного
режима с настройками и приёмкой; RAM-inbox контейнера от него не зависит.

## Что уже постоянно

Классификаторы и таблицы каждого WAN уже сохраняются между переключениями.
Динамический Address List допускает новые соединения к выбранному WAN или
взвешенному набору. Маркированные соединения используют таблицу своего WAN.
Оставшиеся переключения policy/main-маршрутов нужны для начального поиска,
трафика самого роутера и совместимых source-routing правил.

Текущий цикл проверяет `disabled` перед командой: он не выполняет одинаковый
`enable/disable` каждую секунду. Изменение distance/gateway вместо этого,
пересоздание маршрутов или переключение routing rules также меняет постоянную
конфигурацию и само по себе не решает задачу записи на носитель.

## Проверенная схема

1. Постоянный рекурсивный default каждого WAN ссылается на выделенный контрольный
   IPv4-адрес. Постоянный host-route разрешает его через конкретного провайдера.
2. `check-gateway=ping` проверяет этот адрес. Статическое правило RAW/output
   блокирует контрольный ICMP, пока соответствующего допуска нет в динамическом
   Address List. При изменении допуска меняется только RAM-запись.
3. При закрытом допуске RouterOS помечает next-hop недоступным и выбирает другой
   маршрут по distance. Настройки маршрута и флаг `disabled` сохраняются.
4. При закрытии обоих каналов активного main-default нет. Проверенный сосед OSPF
   получает отзыв default при `originate-default=if-installed`; при восстановлении
   default снова появляется. Отдельные source-bound SLA-пробы продолжают работать.

Сначала выполнены пять проверок одного маршрута. Расширенный опыт с двумя WAN
и реальным OSPF-соседом прошёл семь проверок. При всех переходах сохранены
поля собственных статических маршрутов, routing rules и RAW-правил. Контрольные
адреса отвечали внутри изолированного стенда; это не проверка публичных провайдеров.

| Переход | Наблюдение в опыте |
|---|---:|
| Основной закрыт RAM-допуском → резерв выбран | 13,54 с |
| Оба закрыты → default отозван у OSPF-соседа | 30,69 с |
| Основной восстановлен → default появился у соседа | 9,46 с |

Это время ожидания состояния в конкретном прогоне, включая проверку шлюза,
опрос наблюдателя и OSPF; оно не является измерением пользовательского простоя
или гарантией задержки. Использовались обычные интервалы проверки RouterOS.

## Что мешает включить это по умолчанию

- Проверка шлюза добавляет задержку после SLA-решения. При обычных параметрах
  ICMP выполняется раз в 10 секунд, gateway закрывается после двух таймаутов.
  Параметры `/routing/settings` общие для устройства: их нельзя незаметно менять
  ради SD-WAN, влияя на чужие маршруты.
- Проверочные цели должны быть независимы от измерений SLA. Блокирование того же
  ICMP, по которому определяется восстановление WAN, создаёт обратную связь и
  может помешать возврату. Дополнительная цель также может отказать самостоятельно.
- В проверенной схеме нужны разные контрольные IP для разных WAN. Попытка
  использовать `gateway=IP@обычная-FIB-таблица` отклонена RouterOS 7.24.5; её нельзя
  считать работающим способом разделить одинаковые цели. Разрешение через VRF
  — отдельная схема, здесь не проверенная.
- Нужны проверки DHCP/PPPoE/LTE и смены адреса/шлюза, VPN underlay, отдельных SLA
  политик, drain/PCC, ответов WAN/DNAT и перезагрузки с пустым RAM-допуском.
  Host-route к контрольной цели также требует учёта трафика к самому этому IP.
- Полный SLA должен управлять допуском. `check-gateway` служит исполнительным
  механизмом; один ping не заменяет RTT, потери, джиттер, кворум и удержание возврата.

Поэтому 0.4.0 сохраняет прямое управление статическими маршрутами при реальной
смене WAN. Исследованный вариант подходит как основа будущего опционального
режима с меньшим числом записей и явно заданным временем сходимости.
