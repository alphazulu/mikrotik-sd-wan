## Восстановление и выявленные ошибки

При неизменном выборе intent не переписывается. При недоступном heartbeat
процесс ждёт RAM lease, без записи на каждом опросе. Истечение аренды передаёт
выбор нативному алгоритму. Ошибочный intent не заменяет хороший cached plan,
а допустимость WAN повторно проверяется по текущему SLA.

Даже здоровый нативный резерв и преждевременный свежий ACK не позволяют
подтвердить контейнерную установку без lease/metadata. Проверен реальный
таймаут, зашифрованное восстановление и reboot. Проверка обновления framework
обнаружила неполное архивирование трёх служебных RSC; SDK исправлен: сохраняет
их старые flash/root файлы до перезаписи и запечатывает previous manifest до
payload/arm. Регрессия намеренно меняет все три версии и подтверждает их откат.
Текущий recovery worker/watchdog остаётся механизмом выполнения восстановления;
основная конфигурация и предшествующие файлы пакета возвращаются из backup/archive.

SIGSTOP данным способом RouterOS для PID1 игнорируется; успешное испытание
SIGSTOP не заявляется. Реальны проверки разрыва heartbeat при живом процессе
и жёсткого SIGKILL. При reboot проверяется сходимость policy и совпадение boot
fence, а не первый промежуточный снимок после появления healthy-метрик.

Начальная задержка 200 мс на направление также рушила HTTP-кворум; для отдельной
проверки SLA использованы 90 мс/направление, RTTоколо 180 мс при доступном кворуме.
Две настройки тестов уточнены для стенда с длительной историей: REST
place-before использует фактический ID первого правила; обычная установка
проверена со штатными 120 с SDK (подготовка 65,77 с). Оставшиеся отрицательные сценарии также используют штатные 120 с,
чтобы загрузка payload не поглощала их короткий deadline до arm. Ошибочные первые попытки и замеры оставлены в runtime.

Инцидентный voice-jitter при десяти VM не выдавался за регрессию алгоритма:
историческая нативная timing-матрица выполнялась на исходных пяти VM,
затем дополнительный контейнерный стенд снова поднят.

## Финальное состояние и ограничения

Оба пятиузловых стенда работают. На исходном — canonical native backend;
на отдельном — один активный непривилегированный контейнер, один actuator,
start-on-boot=yes, debug metrics/logging выключены. Нет test jobs/правил/
forward/групп; proxy без impairments, APN/provider fixtures исходного стенда
пусты, package source hashes соответствуют результату. Два аудита:
`runtime/container-final-clean-state.json` и
`runtime/container-native-final-clean-state.json`.

Физические ARM/LTE, длительный hardware/load/soak, IPv6/DPI и миграция
существующие сторонние OSPF/VPN-маркировки не заявляются выполненными. Guard сохранён.
Права RouterOS API общие, а не file-scoped; выделенный пользователь ограничен
адресом veth, остальные права явно отключены. Инструкция: [CONTAINER.md](CONTAINER.md).


Локальные `runtime/` отчёты, учётные данные и снимки устройств не входят в
репозиторий. Методика повторения проверок: [TESTING.md](TESTING.md).
