## Что доказывают сценарии соединений

- Удалённый источник получает ответы от трёх основных и трёх дополнительных WAN IP. Дополнительно проверены ответы при отсутствии выбранного SLA default, когда сам underlay доступен, и доступ с LAN после повторной установки.
- Долгая входящая native API-сессия через резервный WAN3 остаётся на WAN3. DNAT к client102 отвечает через тот же WAN3, хотя его исходящая политика предпочитает WAN2.
- Два параллельных TCP/NAT потока .101 и .102 получают разные policy/WAN marks. Ухудшение voice SLA переводит только .102, удаляет его прежнюю запись, сохраняет .101 и входящее управление. Возврат также удаляет fallback-запись.
- Тихий blackhole WAN1 удаляет старое NAT-состояние .101; замещающий поток идёт через WAN2. Возврат .101 с WAN2 не удаляет соединения .102 на том же WAN2. Пробы сохраняют отдельные marks.

Удаление conntrack не посылает TCP RST и не переносит TCP между разными публичными NAT IP. Приложения должны переподключиться. Старые немаркированные/FastTracked потоки до установки требуют отдельного решения при миграции; их массовая очистка автоматически не выполняется.

## Что доказывают сценарии установки

1. Установка идёт через локальный scheduler; подтверждение отправляется после открытия нового API-соединения. Новый пароль backup отсутствует в RouterOS log.
2. Установочная сессия закрыта, ACK не отправлен, файлы нового пакета отличаются. Watchdog самостоятельно возвращает encrypted backup, перезагружает CHR и восстанавливает все семь прежних core/config файлов с точным сравнением содержимого.
3. В конец установщика намеренно добавлены посторонняя address-list запись, отключение API и ошибка. Без внешних команд отката восстановлены API, прежние файлы и конфигурация; посторонняя запись исчезла.
4. Ошибка нового контроллера восстанавливает прежний source, флаги принятых маршрутов/FastTrack, strict rp-filter и scheduler. Неудачная миграция со старого пакета без dataplane возвращает старый контроллер, убирает новые mangle/list и удаляет ранее отсутствовавший RSC.

В этой итерации устранено зависание CHR на последовательности routing-rule move/rollback/reinstall: собственные local bypass rules пересоздаются перед явным первым `.id`, без move. Повторная установка, baseline rollback/reinstall и локальный доступ к alias WAN IP проверены после изменения. Найден и исправлен пустой manifest архива; теперь его полнота проверяется до загрузки нового пакета, а аварийные тесты сравнивают изменённые файлы целиком.

GUI раньше не запрашивал `comment` в API whitelist mangle: свои правила ошибочно считались сторонними. Добавлено поле и регрессия с проекцией `.proplist`; настоящие чужие marks по-прежнему блокируют генерацию. В Windows live GUI читал настройки, генерировал и показывал план, активный JSON роутера не изменился. Финальный автоматический снимок экрана недоступен при блокировке рабочего стола; функциональные проверки выполнены независимо от него.
