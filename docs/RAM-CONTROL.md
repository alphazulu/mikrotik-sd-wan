# Обмен контейнера с RouterOS в RAM

Русский | [English](RAM-CONTROL.en.md)

В 0.4.0 контейнер передаёт выбранные WAN через динамическую запись Address List.
Файл `sdwan-container-intent.json` больше не используется для текущих решений.
Контроллер остаётся на MikroTik; общая RSC-логика измеряет SLA, проверяет выбор,
применяет маршруты и очищает соответствующий conntrack.

## Контракт

Один inbox: `list=sdwan-container-intent`, `address=127.0.0.1`, `dynamic=yes`.
Комментарий содержит JSON не более 32768 байт UTF-8. Новая запись создаётся
только после появления RAM-heartbeat; существующая обновляется по ID только
после проверки имени списка, адреса, динамичности и отсутствия дублей.
Статическая либо неоднозначная запись не перезаписывается.

Протокол 2 сохраняет прежние boot/configuration/revision, instance/sequence,
возраст наблюдения и шестисекундный heartbeat. Новый процесс не вытесняет
другого владельца с живой арендой. RouterOS повторно проверяет предложенный WAN
по текущим SLA и приоритетам; старый intent не удержит здоровый резерв после
восстановления основного канала.

При неизменном выборе контейнер не обновляет inbox. При исчезновении записи
или неверной её структуре адаптер снимает ownership. Неверный JSON, старые
поколения и чужие команды не заменяют уже принятый план. Невалидная структура
также убирает разрешение записи из метаданных: процесс ждёт, сохраняя API-сессию,
вместо повторного подключения на каждом опросе. Потеря heartbeat возвращает
решение нативному алгоритму.

Перезагрузка удаляет динамическую запись. После новых SLA-наблюдений контейнер
получает новый boot fence и создаёт inbox заново. Сохранять промежуточные решения
на flash для этого не требуется. Динамические записи не сохраняются в конфигурации
и пропадают после перезапуска согласно [документации MikroTik](https://manual.mikrotik.com/docs/firewall-and-quality-of-service/firewall/address-lists/).
Поведение дополнительно проверяется на версии RouterOS стенда.

## Обновление с протокола 1

Образ 0.4.0 и его RSC-адаптер составляют одну версию протокола. При несовпадении
версий процесс ждёт без heartbeat и intent-записей; доступность поддерживает
нативный контроллер. Это безопасное промежуточное состояние, а не успешная
активация нового контейнера. Watchdog не подтверждает установку, пока нет
принятой живой аренды.

Для смены образа используйте отдельный этап обслуживания:

1. Сохраните конфигурацию и backup, затем штатной транзакцией переключите ту же
   SD-WAN-конфигурацию в `controller_backend=routeros`.
2. Остановите старый управляемый контейнер. Сохраните его архив, каталог и
   конфигурацию для возврата. Подготовка существующей записи не заменяет rootfs.
3. При повторном импорте используйте новое имя архива и новый каталог хранения.
   Удаляйте только прежнюю остановленную запись своего контейнера и его два
   readonly-mount из списка `sdwan-controller`. Чужие объекты оставьте владельцу:
   SDK намеренно отказывает при занятом или неоднозначном имени.
4. Используйте согласованные SDK, каталог SHA256 и образы 0.4.0. Подготовьте
   контейнер, затем примените `controller_backend=container` обычной защищённой
   транзакцией. Подтверждение требует текущего SLA и живого protocol-2 lease.

Не удаляйте прежний intent-файл заранее: старый образ/адаптер может потребовать
его при возврате к прежней версии. После подтверждённого перехода файл можно
удалить. Автоматическая замена rootfs и атомарный откат образа не добавлены этим
изменением; установка и откат сетевой конфигурации используют прежний watchdog.

## Что продолжает записываться

RAM-inbox устраняет запись intent на носитель. Он не отменяет изменения JSON,
backup/установку, изменения статических маршрутов, логи на диск, swap или
служебные записи RouterOS. В частности, новые API-входы могут сопровождаться
служебной записью; поэтому важны одна постоянная сессия и отдельный контроль
до измерения NAND. Счётчик секторов также учитывает отложенную запись, а не
только команду в момент его чтения.

Вариант без переключения статических маршрутов исследуется отдельно:
[постоянные маршруты и RAM-допуск](RAM-ROUTE-DESIGN.md). В 0.4.0 он не включён
в рабочий dataplane.
