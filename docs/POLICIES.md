# Политики клиентов, групп и приложений

Новая итерация реализует выбор WAN по сочетанию IP/подсети источника, группе адресов, назначениям, входному интерфейсу/VLAN, протоколу и портам. Решения SLA и переключения выполняются на RouterOS. GUI редактирует декларативный JSON и устанавливает прежний пакет из восьми RSC и JSON. Приёмка завершена: 147 unit, 121 проверка CHR и пять Windows GUI-наборов. [Результаты](POLICIES-VALIDATION.md).

## Настройка в GUI

1. Получите настройки устройства и создайте конфигурацию либо откройте JSON.
2. На вкладке «Группы адресов» задайте имя группы и IPv4 адреса/подсети через запятую. Можно создать группы клиентов и назначения сервисов.
3. На вкладке «Клиенты и приложения» добавьте правило. В диалоге «Маршрут и приоритет» укажите имя, source, собственную таблицу `sdwan-…`, SLA, prefer/strict и порядок WAN. Во вкладке «Группа и приложение» задайте селекторы.
4. Для всех клиентов используйте source `0.0.0.0/0`; пустой source оставьте только общей политике с таблицей main. Для клиента или подсети можно сочетать source и группу — это пересечение, а не объединение.
5. Задайте явные приоритеты пересекающимся правилам: меньшее число выполняется раньше. Кнопки «Выше/Ниже» переставляют правило и присваивают приоритеты всем частным политикам. Общая политика всегда последняя.
6. Нажмите «Проверить» и посмотрите план изменений. Неоднозначные пересечения отклоняются; упорядоченные показываются в проверке. Полное перекрытие одним предыдущим правилом отмечается отдельно.

Все заданные условия правила соединяются **И**. Участники одной адресной группы соединяются **ИЛИ**. При первом совпадении дальнейшие правила не рассматриваются; недоступность выбранного WAN не означает переход к следующей политике. Резерв выбирается только из WAN той же политики. Strict допускает ровно один WAN.

При изменении групп, условий или порядка правил пересоздаются управляемые исходящие клиентские соединения для новой классификации. Входящие WAN-сессии управления и probes сохраняются. Повторное применение тех же селекторов/групп/порядка не пересоздаёт соединения. Обычные SLA failover/failback очищают только затронутые policy/WAN marks.

## Формат JSON

Дополнительный top-level объект `groups`:

```json
"groups": {
  "phones": ["192.168.50.101/32", "192.168.50.102/32"],
  "voice-services": ["203.0.113.0/24"]
}
```

Пример дополнительной политики:

```json
{
  "name": "voice-app",
  "source": "0.0.0.0/0",
  "source_group": "phones",
  "destination_group": "voice-services",
  "in_interface": "vlan-voice",
  "protocol": "udp",
  "dst_ports": "5060,10000-20000",
  "priority": 10,
  "table": "sdwan-voice-app",
  "profile": "voice",
  "mode": "prefer",
  "wans": ["wan1", "wan2"],
  "allow_degraded": false
}
```

Это фрагменты существующей конфигурации. VLAN, адреса, NAT и необходимые firewall разрешения должны существовать заранее. `in_interface` — фактический входной L3 интерфейс RouterOS, не номер VLAN и не физический порт под bridge. WAN в массиве `wans` задаются именами из JSON, например wan1, а не именами физических интерфейсов.

| Поле политики | Значение |
|---|---|
| source | IPv4 адрес/подсеть; `0.0.0.0/0` — любой источник; пусто — только общая политика |
| source_group / destination_group | Имя объявленной адресной группы; пусто — без ограничения |
| destination | Дополнительная IPv4 подсеть назначения, пересекается с destination_group |
| in_interface | Уже настроенный логический интерфейс, включая VLAN; пусто — любой клиентский вход |
| protocol | any / tcp / udp / icmp; отсутствие означает any |
| src_ports / dst_ports | Список портов и диапазонов, например `80,443,10000-20000`; только TCP/UDP |
| priority | Уникальное целое 1..999999, меньшее раньше; обязательно для всех пересекающихся частных правил |

Допускается до 64 политик, 64 групп и 256 непересекающихся участников в группе; до 15 непересекающихся элементов в каждом списке портов, диапазон 1..65535. Источники/назначения — IPv4, без FQDN и вложенных групп. Старые JSON без новых полей совместимы; прежние непересекающиеся source политики сохраняют порядок.

## RouterOS и ограничения

Группы создаются как собственные `sdwan-group-*` address lists. Classifier и fail-closed guard используют одинаковые селекторы. У составных политик не создаётся широкое source-only routing rule: оно обошло бы ограничения портов/назначений. В собственной таблице политики есть blackhole default distance254; без разрешённого WAN поток не уходит через main/default. Старые matcher constraints удаляются при редактировании правила.

Названия приложений в правилах — описание администратора. Классификация выполняется по заданным адресам/протоколам/портам, без DPI и определения приложения внутри шифрованного HTTPS. Наборы адресов сервисов поддерживаются администратором.

Правила применяются к исходящим клиентским потокам. Входящие WAN/DNAT, связанные ответы, health probes и назначения `local_networks` сохраняют свои исключения. [Совместимость OSPF/VPN](OSPF.md) требует отдельного согласования; guard сторонних mark rules не отключён. Новые Internet-политики не создают защиту неизвестных филиальных prefix автоматически.


Локальные `runtime/` отчёты, учётные данные и снимки устройств не входят в
репозиторий. Методика повторения проверок: [TESTING.md](TESTING.md).
