# GUI: от подключения к готовой конфигурации

Запуск в Windows: двойной щелчок **`Configure-SD-WAN.cmd`**. Зависимостей pip нет, нужен Python с Tkinter.

## 1. Получить настройки MikroTik

Введите адрес API, логин и пароль, затем нажмите **«Подключиться и получить настройки»**. Файл с паролем не требуется. Пароль скрыт в форме и не сохраняется в конфигурации или отчёте обнаружения.

| Подключение | Пример |
|---|---|
| RouterOS API | `api://192.168.88.1:8728` |
| RouterOS API с TLS | `apis://router.example.net:8729` |
| REST с TLS | `https://router.example.net` |
| Подготовленный стенд | Кнопка «Лаборатория», затем подключение; `api://127.0.0.1:18728` |

Соответствующий сервис должен быть включён на MikroTik и доступен с компьютера. Мастер не включает сервисы и не открывает firewall. Обычный API передаёт учётные данные без шифрования; используйте его в доверенной сети управления или через VPN. Для `apis://` нужен сертификат сервера; поле CA позволяет указать доверенный PEM. Проверяются имя и цепочка сертификата. REST HTTP разрешён только для loopback, например `http://127.0.0.1:18080` на стенде.

Мастер читает identity, версию, интерфейсы, IP, маршруты, routing rules, DHCP/PPPoE, bridge, список WAN, NAT, FastTrack и routing marks. Если уже установлен наш SD-WAN, читает его активную конфигурацию. Списки пользователей, пароли PPPoE и закрытые ключи не запрашиваются. Инвентаризация сохраняется локально в `runtime/discovery-*.json`.

Чтение настроек не изменяет MikroTik. Ошибки прав показываются в журнале; при отсутствии данных для проверки конфликтов создание конфигурации блокируется.

## 2. Указать внешние интерфейсы

На вкладке **«1. Выбрать внешние интерфейсы»** отметьте WAN галочками в первом столбце. При подключении ни один интерфейс не выбран автоматически. Кнопка «Отметить рекомендованные» использует текущий SD-WAN, список WAN и найденные шлюзы как подсказки.

Для каждого WAN проверьте IPv4, шлюз и приоритет: **1 — основной**, 2 и далее — резерв. При нескольких адресах или шлюзах выберите нужные в нижней форме. Если шлюз не удалось определить, укажите его явно; мастер не подставляет адрес `.1` по предположению. Интерфейс может иметь произвольное имя, в том числе с пробелами.

Для рекурсивного маршрута мастер использует фактический следующий шлюз из `immediate-gw`, а не удалённую контрольную цель из поля `gateway`. Если IPv4 или шлюз пусты, кнопки «Далее» и «Создать конфигурацию» показывают имя WAN и причину, возвращают на шаг 1 и выделяют нужную строку. Интерфейсы без адреса и динамические WAN не включаются кнопкой рекомендаций.

Адреса должны быть уже назначены на MikroTik. Порты, входящие в bridge, не используются как самостоятельные L3 WAN: выбирайте соответствующий bridge/VLAN. Перекрывающиеся подсети WAN требуют отдельной схемы VRF и отклоняются.

## 3. Цели и создание конфигурации

На вкладке **«2. Контроль каналов»** задайте ICMP-цель и контрольные TCP/HTTP/DNS-цели. Они должны быть доступны через каждый выбранный WAN. Для уже настроенного устройства можно сохранить действующие цели и правила клиентов. SLA-профили существующего SD-WAN переносятся в редактор.

Имена контрольных целей допускают точки: например, `ya.ru`. Имя служит идентификатором цели; фактический адрес указывается отдельно в поле «IP / DNS-имя».

Нажмите **«Создать конфигурацию из выбранных интерфейсов»**. На шаге 3 откроются формы WAN, SLA, клиентов, порядка каналов и таймеров. Локальные сети получаются из адресов невыбранных интерфейсов. Если исключён канал, необходимый сохранённой политике клиента, мастер попросит исправить выбор.

Для нового устройства исходные таймеры: интервал 5 с, 3 плохих окна, 6 хороших, hold-down 60 с, quorum 2. Это начальные значения для настройки, а не согласованный SLO. Для существующего SD-WAN сохраняются его таймеры и лабораторные цели, если выбран их перенос.

**Генерация остаётся локальной.** Дальнейшие действия:

1. **«Проверить»** — проверить конфликты и значения.
2. **«Сохранить JSON»** — сохранить редактируемый файл. Предлагаемое имя — `config/discovered-<identity>.json`.
3. **«Файлы RouterOS»** — создать девять файлов: `sdwan-config.json` и восемь `.rsc` ядра и защищённой установки в выбранной папке.
4. **«План изменений»** — прочитать текущие объекты и показать план, включая исходные маршруты и FastTrack.
5. **«Установить на MikroTik»** — подготовить backup, запустить локальный worker и подтвердить результат через новое API-соединение.

Установка сохраняет снимок и исходные флаги отключения объектов. Существующие default routes выбранных WAN отключаются по точным селекторам, даже если у них нет комментария. FastTrack, мешающий policy routing, отключается с сохранением исходного состояния. Если объект изменился после обнаружения, установка требует получить настройки заново. **«Откат к исходному»** восстанавливает сохранённые флаги и удаляет объекты проекта.

Контроллер, SLA и переключение исполняются на MikroTik. После установки конфигуратор можно закрыть.

Маркировка соединений, симметричные ответы WAN/DNAT и выборочная очистка conntrack при переключении входят в создаваемый комплект автоматически. Подробности и границы — [DATAPLANE.md](DATAPLANE.md).

## Границы этой версии

- Установка проверена и разрешена для RouterOS **7.24.5**.
- Поддерживаются **static, DHCP-client, PPPoE и native LTE IPv4 WAN**. Для PPPoE выбирайте логический PPPoE client, для DHCP — интерфейс клиента, включая VLAN. Клиент провайдера должен существовать заранее. Временный адрес отображается только для справки; JSON содержит тип и интерфейс, адрес и шлюз контроллер получает на RouterOS. Можно выбрать включённый клиент без текущей аренды/сессии; до появления адреса и свежего SLA канал закрыт. Подробнее: [DYNAMIC-WAN.md](DYNAMIC-WAN.md).
- Генератор использует существующие IP, NAT и базовый firewall; их первичная настройка в этот мастер не входит. Отсутствие исходящего NAT показывается в журнале.
- Активные `mangle mark-routing` требуют согласования и блокируют генерацию. Сложные схемы VRF, рекурсивных шлюзов и стороннего policy routing требуют отдельного проектирования.
- Кнопка отката восстанавливает baseline проекта. Аварийная ошибка установки или потеря подтверждения запускает полный бинарный restore с перезагрузкой. Требуются права reboot и sensitive; подробности — [DEPLOYMENT.md](DEPLOYMENT.md).

Лабораторный пример: [config/sdwan.json](../config/sdwan.json). Для своего устройства создайте конфигурацию через мастер.

Проверки и снимки GUI: [WIZARD-VALIDATION.md](WIZARD-VALIDATION.md).

Для LTE мастер показывает назначенный APN профиль; JSON хранит kind=lte/interface/apn_profile без runtime IP/gateway. APN automatic default согласуется с SD-WAN, исходные значения сохраняются для rollback. Подробности и ограничения проверки оборудования: [LTE.md](LTE.md).

## Диагностика и расширенные политики

Вкладка «Диагностика» доступна после подключения без генерации нового JSON: WAN/SLA/выбор политик/история, ручное или автоматическое чтение, экспорт и объяснение нового потока. [Инструкция](DIAGNOSTICS.md). В редакторе появились «Группы адресов» и диалог политик с условиями IP/group/interface/protocol/ports, приоритетами и проверкой пересечений: [POLICIES.md](POLICIES.md).


Локальные `runtime/` отчёты, учётные данные и снимки устройств не входят в
репозиторий. Методика повторения проверок: [TESTING.md](TESTING.md).

## Существующие mangle-правила

Мастер может подготовить черновик со списком конфликтов, сохраняя блокировку установки до миграции старой маркировки. [Порядок перехода и локальные отчёты](MIGRATION.md).
