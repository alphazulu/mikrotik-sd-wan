# API, место и архивы установки

Русский | [English](MAINTENANCE.en.md)

Поиск отдельного файла использует API query по точному имени, включая корректный
приоритет `flash/` над legacy root. Полный каталог не пересылается на каждый
опрос журнала. Загрузка существующего текста сравнивает содержимое: если оно
одинаковое, `/file set` не выполняется. Новые файлы по-прежнему создаются пустыми
и заполняются отдельным `set`, чтобы содержимое не копировалось в log.

Перед первым изменением файлов установки проверяется внутреннее свободное место:
резерв 1 МиБ плюс удвоенный размер payload. Это нижняя оценка для preflight, не
предсказание размера зашифрованного backup; bootstrap всё равно проверяет его
успешное создание до изменения сети. Доступность и место для root-dir на внешнем
носителе проверяются отдельно при подготовке контейнера.

## Посмотреть и очистить старые архивы

CLI по умолчанию только показывает план; нужны обычные параметры подключения,
credentials и ожидаемая identity своего лабораторного устройства:

```sh
python3 sdwan.py --url api://127.0.0.1:18728 prune-backups --keep 3
python3 sdwan.py --url api://127.0.0.1:18728 prune-backups --keep 3 --execute
```

Сохраняются N последних подтверждённых групп по времени журнала/метаданным,
текущая группа независимо от времени, транзитивные зависимости её manifest и
группы без надёжной даты. При равной дате на границе сохраняются все связанные
группы. `keep` допускает 1–20. Текущая конфигурация, baseline, secret mounts и
пользовательские файлы никогда не являются кандидатами.

Удаляться могут только строго именованные файлы `sdwan-before-TOKEN.backup`,
`sdwan-prev-TOKEN-INDEX`, `sdwan-infra-prev-TOKEN-INDEX`, `sdwan-txn-TOKEN.json`
для проверенного завершённого журнала того же устройства. TOKEN —24hex символа.
Неизвестные/orphan файлы без подтверждающего журнала оставляются. Журнал старой
группы удаляется последним, чтобы прерванную очистку можно было продолжить.

Pending/recovery-failed, непонятный журнал, несовпадение identity/token или
различающиеся flash/root копии блокируют автоматическое удаление. Между каждым
удалением повторно проверяются текущая транзакция и точный ID файла. Ошибка
прерывает оставшуюся очистку, не запускает переустановку или rollback.

## Автоматически после подтверждённой установки

Режим включается явно во вкладке GUI «Файл и локальные сети» либо в полном JSON:

```json
{"maintenance": {"backup_keep": 3}}
```

Это фрагмент существующей конфигурации. Старые JSON без `maintenance` сохраняют
прежнее поведение: автоматического удаления нет. План установки показывает
включённую политику и текущую оценку очистки. После нового committed-пакета
кандидаты вычисляются заново: новая транзакция всегда защищена. Если очистка
заблокирована, установка остаётся committed, а причина выводится отдельно.

Обслуживание выполняется один раз конфигуратором/CLI после ACK. Отдельного
периодического задания или записи счётчика на flash нет. Если клиент закрылся
после ACK, очистку можно выполнить отдельной командой; работа SD-WAN от неё
не зависит. Recovery key на компьютере не удаляется автоматически.

Работающая RAM-статистика/web описана в [STATISTICS.md](STATISTICS.md).
Первоначальный проект сохранён в [STATISTICS-DESIGN.md](STATISTICS-DESIGN.md).
