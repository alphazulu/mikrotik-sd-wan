# Обязательное unit-покрытие контейнера

При каждом изменении контейнера проверяются оба Rust-профиля (`base` и `web`),
основной цикл `main.rs`, все библиотечные модули и браузерный JavaScript.
Требование владельца закреплено в [правилах контейнера](../container-controller/AGENTS.md).

На Linux amd64 / WSL с установленным Rust SDK проекта:

```bash
python3 tools/install_container_test_tools.py
python3 tools/container_checks.py
```

Проверка требует **100% исполняемых строк и функций каждого рабочего файла**.
Из расчёта исключаются только исходники тестов. Ветвления выводятся отдельно;
покрытие не заменяет проверки ожидаемого результата и обработку ошибок.
Инструменты покрытия устанавливаются только на машине сборки, в scratch-образ
они не попадают. Cargo LLVM Coverage закреплён на0.9.1, архив проверяется SHA256.

JSON-отчёты, журналы и результат лежат в `runtime/container-unit/` и не публикуются
в исходниках. `--output` или `SDWAN_CONTAINER_COVERAGE` позволяют выбрать другой
каталог. `SDWAN_LLVM_COV` задаёт путь к установленному cargo-llvm-cov той же версии.
Используйте `CARGO_HOME`/`RUSTUP_HOME` своего SDK, если он расположен вне проекта.

Штатная сборка `python3 container-controller/build.py` проверяет успешный результат
покрытия, привязанный SHA256 ко всем текущим файлам контейнера и инструментам
проверки. При изменении исходников или тестов старый результат перестаёт подходить,
и проверка выполняется заново. Пропуска проверки в утилите нет. SHA256 проверенного
набора сохраняется в отчёте каждого образа.

CI запускает такую же проверку перед сборкой шести scratch-образов. Отчёты CI
сохраняются отдельным артефактом, в том числе при ошибке. При изменении поведения
после unit-проверки дополнительно выполняется приёмка конкретного образа на CHR.
Рабочий MikroTik для этих проверок не используется.
