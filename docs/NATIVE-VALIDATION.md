# Проверка нативного SD-WAN — 23.10.2026

Контроллер: только RouterOS script + scheduler на CHR 7.24.5. Python запускал установки, вводил аварии и читал результаты, но не выбирал каналы.

## Итог

- 15/15 интеграционных сценариев на CHR пройдены.
- 19/19 тестов валидации конфигурации пройдены.
- Нативный тест дробных параметров пройден: 0,125 мс → 125 мкс; 0,5% → 50 basis points; 15,0 мс → 15000 мкс.
- DNS + HTTPS с проверкой сертификата к mikrotik.com: 2/2 клиентских адреса.
- GUI Windows: формы, чтение JSON, проверка; screenshot `runtime/screenshots/configurator.png`. Подключение GUI к REST и команда плана проверены отдельно.

|---|---|
| Клиент .101 | Фактически WAN1, подтверждён счётчиками на ISP |
| Клиент .102 | Фактически WAN2 |

| Застывшие ICMP измерения | По stale timeout исключён WAN; старые метрики не признаны healthy |
| Повторный опрос тех же Netwatch данных | Не увеличивает число хороших окон |

| Reboot CHR | Файлы, скрипт и scheduler сохранились; управление каналами восстановилось локально |
| Нативный rollback | Восстановлены исходные routes/rules; baseline проверка прошла 14/14 |
| Повторная установка | SD-WAN и политики восстановлены без дублирования объектов |

Время — измерения одного запуска, не гарантированный SLA. Модель использует окна Netwatch; на этом стенде ICMP измеряет участок через виртуальный ISP до QEMU host alias, а HTTP-цели работают на тестовом хосте. Независимость реальных ISP/контрольных ресурсов и работа под длительной нагрузкой ещё не проверены.

## Артефакты

- `runtime/native-acceptance.json` — все результаты и счётчики.
- `runtime/native-numeric.json` — результат выполнения числового helper именно в RouterOS.
- `runtime/internet.json` — DNS/HTTPS через клиентов.
- `runtime/verification.json` — базовая проверка версии и связности, автоматически учитывающая нативный режим.
- `runtime/pre-native-*.json` — снимки до установки.
- `runtime/native-plan.txt` — план управляемых объектов.
- `runtime/gui-connection-smoke.txt` — результат CLI-команд, вызванных Windows GUI.
