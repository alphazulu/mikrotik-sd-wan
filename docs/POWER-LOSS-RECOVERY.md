# Восстановление после прерывания питания

Русский | [English](POWER-LOSS-RECOVERY.en.md)

**Ограниченная приёмка x86 RouterOS 7.24.5 завершена:** первая установка,
обновление, восстановление подтверждённой копии и свежий трафик проверены в RSC
и локальном контейнере. [Методика, результаты и границы](POWER-LOSS-VALIDATION.md).
Это не гарантия атомарной записи при любом отключении питания.

## Какие данные используются

| Объект | Назначение |
| --- | --- |
| `sdwan-config.json` | Staging для следующего импорта; сам по себе не подтверждает конфигурацию |
| `sdwan-active.json` | Применённая конфигурация, включая кандидата в незавершённой транзакции |
| `sdwan-confirmed-a.json`, `sdwan-confirmed-b.json` | Два чередующихся места для подтверждённой копии |
| `sdwan-confirmed-record` в `/system/script` | Небольшая запись с токеном, identity, revision, размером, контрольной суммой и именем выбранной копии |
| `sdwan-txn-<token>.json` и encrypted backup | Журнал применения и полный откат конфигурации устройства |

Запись `sdwan-confirmed-record` начинается с `#` и читается как JSON-данные.
Она никогда не запускается. Наличие второго файла не делает его допустимым
источником восстановления: выбранная копия должна соответствовать записи.
MD5 используется для обнаружения повреждения, не для аутентификации.

## Установка и подтверждение

Все решения и восстановление выполняются на RouterOS. Конфигуратор подготавливает
файлы, наблюдает и подтверждает результат новым API-подключением.

1. Bootstrap сохраняет старые файлы и создаёт encrypted backup. Watchdog ждёт
   45 секунд перед разрешением следующего этапа.
2. Клиент дополняет журнал полным списком архивов, включая предыдущие файлы
   механизма восстановления. Ещё 45 секунд отделяют эту запись от замены пакета.
3. Worker применяет правила. После готовности контроллера watchdog записывает
   конфигурацию в невыбранную копию и выдерживает 45 секунд.
4. Только затем конфигуратор проверяет результат свежим API-подключением и
   отправляет ACK. Watchdog публикует небольшую подтверждающую запись и отмечает
   транзакцию завершённой.

Резерв времени на три барьера составляет 135 секунд сверх срока транзакции
(по умолчанию 120 секунд). Ожидание записи не требует долгого API-вызова.
Закрытие конфигуратора не запускает следующий этап автоматически.

## Поведение после перезапуска

Динамическая запись `sdwan-deployment-boot` исчезает при перезапуске. Поэтому
определение новой загрузки не зависит только от сравнения uptime. Однократное
задание `sdwan-deploy-startup` запускает watchdog даже при прерывании подготовки
до включения его периодического задания.

Незавершённая транзакция после перезапуска не получает автоматическое
подтверждение. Контроллер закрывает допуск новых интернет-соединений, пока
watchdog восстанавливает прежние файлы и конфигурацию. Если backup ещё не был
готов и сетевой пакет не заменялся, восстанавливаются файлы подготовки.
После полного восстановления из backup файлам даётся 45 секунд перед завершением
отката. Затем SLA собирается заново; conntrack через перезагрузку не сохраняется.

При завершённой транзакции повреждённый или пустой `sdwan-active.json`
восстанавливается только из копии, указанной подтверждающей записью. Проверяются
identity, revision, размер и контрольная сумма. Staging для этого не используется.
Повреждение и active, и выбранной копии приводит к закрытию допуска и ошибке;
система не угадывает, какой из оставшихся файлов следует активировать.

Старая ручная установка без подтверждающей записи не получает копию из staging.
Её создаёт следующее успешное защищённое применение.

## Запись на носитель и границы проверки

Копии и метаданные записываются при явном применении конфигурации или
восстановлении. Обычный опрос SLA не переписывает их. Таймер ожидания хранится
в RAM; очередная итерация watchdog не начинает запись копии заново.

Официальная [документация Files](https://manual.mikrotik.com/docs/system-information-and-utilities/files/)
описывает кеширование записи на некоторых устройствах с NAND до 40 секунд.
Постоянные файлы помещаются в `flash/`, если такой каталог есть. 45-секундный
барьер — запас относительно этого описания, а не системный `fsync`.
[Scripting](https://manual.mikrotik.com/docs/developer-guides/scripting/)
описывает `:convert ... transform=md5`; его исполнение проверено на 7.24.5.
Текущий manual описывает 7.26, поэтому сведения о версиях разделяются.

Проверка x86 показала потерю содержимого при немедленном отключении после
`/file/add contents=...` и после повторной записи файла. Контрольная сумма
обнаружила промежуточное содержимое. Копия после 45-секундного барьера пережила
принудительное завершение QEMU; из неё восстановлен active при отличающемся
staging. Поведение ARM/NAND и аппаратного контроллера питания этим не подтверждено.

Проверены обрывы первой установки, обновления и работы после подтверждения,
оба режима, свежие TCP/UDP-потоки, LTE, VPN, OSPF, исходные образы и очистка.
Неуспешный ранний backup остаётся в результатах отдельным неуспешным прогоном.

См. [защищённую установку](DEPLOYMENT.md) и
[предыдущую функциональную проверку WAN/LTE/VPN/OSPF](MIXED-WAN-VALIDATION.md).
