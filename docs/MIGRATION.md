# Черновик при существующих mangle-правилах

Русский | [English](MIGRATION.en.md)

Мастер позволяет нажать «Создать конфигурацию», даже если в прочитанном снимке
есть активные сторонние `mark-connection`, `mark-routing` или `route`. Это
подготовка черновика: MikroTik при генерации не меняется. По умолчанию программный
`generate()` сохраняет строгую проверку; мастер явно выбирает подготовку
черновика параметром `allow_foreign_mangle=True`.

В шаге 3 появляется отметка «ЧЕРНОВИК» и вкладка «Переход со старых правил».
В ней перечислены ID, цепочки, действия, марки, условия и комментарии
конфликтующих правил. Правила MSS, DSCP и `mark-packet` сами по себе не требуют
отключения. Отключённые правила и собственные объекты `sdwan:v1:` не входят
в список конфликтов. Пользовательские цепочки проверяются также.

При сохранении JSON создаются файлы `<имя>.json.migration.json` и
`<имя>.json.migration.txt`. Предупреждение восстанавливается при повторном
открытии JSON. При экспорте файлов RouterOS рядом создаются
`MIGRATION-REVIEW.txt` и `MIGRATION-REVIEW.json`. Эти локальные отчёты могут
содержать частные параметры маршрутизации и исключены из Git.

## Перед применением

1. Сохраните исходные export/backup и предусмотрите доступ для восстановления.
2. Разберите назначение каждого перечисленного правила. Перенесите нужные
   условия клиентов и назначений в политики SD-WAN. Отдельно проверьте
   служебный VPN-трафик и исключения внутренних/филиальных сетей при OSPF.
3. Отключите только заменённые конфликтующие старые маркировки. Текущая версия
   требует их отключения; автоматического слияния схем маркировки нет.
   Не используйте массовое отключение всех mangle-правил.
4. Заново получите настройки устройства и создайте конфигурацию. Выполните
   «План изменений» и проверьте маршруты до установки.

Кнопка установки заблокирована, пока черновик содержит известные конфликты.
API preflight также читает актуальные правила перед передачей пакета, а native
installer повторяет проверку при ручном импорте. Удаление локального отчёта,
переоткрытие JSON или создание файлов `.rsc` не разрешают обойти эти проверки.
Успешная синтаксическая проверка JSON не означает готовность устройства.

При стандартном порядке `policy-rules` RouterOS проверяет таблицу mangle routing
mark раньше обычных routing rules. Если таблица разрешает назначение, новые
правила сами по себе не заменяют прежнюю классификацию. Поэтому простого добавления
новых правил поверх старых недостаточно для согласованной миграции.
[RouterOS Routing Decision](https://manual.mikrotik.com/docs/user-guides/routing-and-networking-protocols/routing-decision/).
