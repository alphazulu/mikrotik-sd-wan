# Конфигурации и учётные данные

Репозиторий содержит исходники и лабораторные/синтетические примеры. Экспорты реальных устройств, их анализ, сохранённые discovery, пароли, ключи, backup, журналы, диски VM и screenshots не входят в публикацию.

Храните собственные файлы в `runtime/` либо в локальных `config/local*.json`. `.gitignore` исключает эти пути, корневые RSC-экспорты, `config/discovered-*.json`, credentials, keys и `.env`. Игнорирование не защищает уже отслеживаемый Git файл: перед каждым push просматривайте `git diff --cached` и запускайте `python3 tools/audit_public_tree.py`.

CLI credentials имеют отдельный JSON; пароль не является полем SD-WAN-конфигурации. Recovery journals и ключи encrypted backup содержат секреты: ограничьте файловый доступ, включая ACL Windows. Не прикладывайте `runtime/` или экспорт устройства к публичному issue. Для воспроизведения используйте вымышленную конфигурацию с минимальным набором полей.

## API и контейнер

Обычный RouterOS API не шифрует трафик: для удалённого управления используйте API TLS с проверкой имени/CA либо доверенный защищённый канал. Не публикуйте сервис управления в Интернет для работы конфигуратора.

Контейнер использует выделенного пользователя, ограниченного IP своего veth, и изолированную сеть `/30`. Права RouterOS API общие: они не дают ACL на конкретный файл/команду. Реально необходимые права `read,write,policy,test,sensitive,api` задаются явно, остальные отключаются. Пароль и JSON монтируются read-only и отсутствуют в scratch-образе. Исходящий/транзитный доступ контейнера ограничен правилами подготовки.

## Установка и восстановление

Защищённая установка требует полномочий на backup/reboot. Watchdog действует на RouterOS, проверяет свежий API ACK и при ошибке возвращает бинарный backup. Restore перезагружает устройство и возвращает также посторонние изменения после снимка; избегайте параллельного редактирования в этот интервал. Гарантия не распространяется на отказ диска/питания или отключение watchdog оператором.
